# llms.txt Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optional, per-site generation of `/llms.txt` (per language) from the page tree, linking to the pages' Markdown versions, with Markdown URLs switched to `<page-path>.md` while the feature is on.

**Architecture:** `llms.txt` is a dedicated `typeNum` rendered by a TypoScript `PAGE` + `USER` on the site root and mapped to `/llms.txt` via the site's `PageType` enhancer (auto-registered by the existing `AddMarkdownPageTypeMapping` listener). Page selection and rendering are pure, unit-tested classes; a thin controller loads the tree via `PageRepository::getMenu()`, builds URLs via the site router and adds `pageId_<uid>` cache tags.

**Tech Stack:** PHP 8.2+, TYPO3 13.4 / 14, PHPUnit 11 + typo3/testing-framework 9 (unit tests only).

**Spec:** `docs/superpowers/specs/2026-11-16-llms-txt-design.md`

## Global Constraints

- Feature is off by default (`ai_bots_love_markdown.llmsTxt.enabled: false`); with it off, behaviour and generated URLs are byte-for-byte unchanged.
- Settings (exact keys/defaults): `llmsTxt.enabled` bool `false`; `llmsTxt.typeNum` int `2027`; `llmsTxt.excludedDoktypes` string `''`; `llmsTxt.title` string `''`; `llmsTxt.description` string `''` (all prefixed `ai_bots_love_markdown.`).
- Page field `pages.llms_txt`: 0 = Inherit (default), 1 = Include, 2 = Optional, 3 = Do not include; `l10n_mode: exclude`; shown on doktype 254 and on doktypes not in `excludedDoktypes`.
- Only `llms_txt` inherits down the tree; hard rules (doktype lists, `no_search`, `no_index`, `markdown_version = 0`, frontend visibility/language) are per page and never overridable.
- With the feature on: `'.md'` is the **first** PageType map key for the Markdown typeNum; the old `pageTypeSuffix` stays in the map; `'llms.txt'` maps to `llmsTxt.typeNum`.
- `llms.txt` is served as `text/plain; charset=utf-8`; any page other than the site root (or feature disabled) → 404.
- No client/project names in code, tests, docs or commit messages (public repo).
- The user commits; "Commit" steps mean: stop and propose a one-line commit subject in b13/TYPO3 style (`[FEATURE] …`, `[TASK] …`).

## Review Focus

1. Titles/descriptions containing `[`, `]`, newlines or leading/trailing whitespace → link text escaped, note collapsed to one line (Task 3 test `escapesBracketsAndCollapsesWhitespace`).
2. Level-1 page excluded by hard rule (sysfolder) but children listed → section heading still uses its title; children still listed (Task 2 test `excludedLevel1FolderStillProvidesHeading`).
3. Site settings written nested (`ai_bots_love_markdown: { llmsTxt: { enabled: true } }`) instead of flat dotted keys → listener still detects them (Task 4 test `readsNestedSettings`).
4. Root and language-root Markdown URLs: `/index.md`, `/en/index.md`, `/.md`, and the legacy `/ai-bots-love.md` → all resolve to the root page (Task 5 tests).
5. A real slug that merely contains `.md` in the middle (`/docs.md-guide`) or `/llms.txt` → untouched by the Markdown request middleware (Task 5 test `leavesNonMarkdownPathsAlone`).

### Task 2: Page selector (inclusion, inheritance, sections)

**Files:**
- Create: `Classes/LlmsTxt/LlmsTxtPageSelector.php`
- Test: `Tests/Unit/LlmsTxt/LlmsTxtPageSelectorTest.php`

**Interfaces:**
- Consumes: `MarkdownExclusionService::isExcluded(array $pageRecord, ?Site $site): bool`, Task 1 classes.
- Produces: `LlmsTxtPageSelector::select(array $level1Pages, Site $site, LlmsTxtSettings $settings): LlmsTxtStructure`
  - Input page arrays: keys `uid, title, doktype, no_search, no_index, markdown_version, llms_txt, description, abstract, children` (`children` = list of the same shape, tree order).

Algorithm (depth-first, pre-order, starting with inherited mode `Include`):
```
for each level-1 page L:
    section = new section titled L.title
    walk(L, inherited = Include, section)
    keep section only if it has entries
walk(page, inherited, section):
    own = LlmsTxtMode::fromRecordValue(page.llms_txt)
    effective = own === Inherit ? inherited : own
    if !hardExcluded(page) and effective !== Exclude:
        entry -> (effective === Optional ? optional list : section)
    for child in page.children: walk(child, effective, section)
hardExcluded = exclusionService.isExcluded(page, site)
            || doktype in settings.excludedDoktypes
            || (bool) no_search || (bool) no_index
note = first non-empty of trim(description), trim(abstract), else ''
```

- [ ] **Step 1: Write failing tests** (real `MarkdownExclusionService`, site with `excludedDoktypes '3,4,6,7,199,254,255'`):
  - `listsDeepPageUnderItsLevel1Section`: L1 "Programs" → child → grandchild "Master" → 1 section "Programs" with entries `[Programs, child, Master]` in that order.
  - `excludeOnFolderInheritsToChildren`: folder (254, `llms_txt 3`) with child page → no section.
  - `childCanReincludeInsideExcludedFolder`: same, child `llms_txt 1` → section titled by folder with just the child.
  - `excludedLevel1FolderStillProvidesHeading`: folder 254 inherit, child page → section title = folder title, entries = [child].
  - `optionalInheritsAndMovesToOptional`: L1 `llms_txt 2` with child → no section; `optional` = [L1, child].
  - `hardRulesNotOverridable`: page with `llms_txt 1` and `no_index 1` → not listed; same for `no_search 1`, `markdown_version 0`, doktype in `settings.excludedDoktypes`.
  - `noteFallsBackToAbstract`: description `'  '`, abstract `'A'` → note `'A'`.
- [ ] **Step 2:** Run → FAIL.

- Consumes: Tasks 1–3, `PageTypeMap::setting` not needed (use `LlmsTxtSettings`, `MarkdownPageType::getTypeNum`).
- Produces: `LlmsTxtController::render(string $content, array $conf, ServerRequestInterface $request): string`

Behaviour:
- Settings disabled, or `frontend.page.information` id ≠ `$site->getRootPageId()` → throw `ImmediateResponseException` with `ErrorController::pageNotFoundAction($request, …)`.
- Tree: `PageRepository` (`makeInstance`, frontend context) `getMenu($pid, '*', 'sorting', '', false)` recursively from the root; this applies hidden/time/group restrictions and language overlay.
- URL: `(string)$site->getRouter()->generateUri($uid, ['_language' => $request->getAttribute('language'), 'type' => markdownTypeNum])`.
- Title/description: setting, else root page record (`title`, `description`) from `PageInformation`.
- Cache tags: `$request->getAttribute('frontend.cache.collector')->addCacheTags(new CacheTag('pageId_' . $uid))` for the root and every traversed page.

TypoScript (append to `setup.typoscript`):
```
aiBotsLoveMarkdownLlmsTxt = PAGE
aiBotsLoveMarkdownLlmsTxt {
    typeNum = {$ai_bots_love_markdown.llmsTxt.typeNum}
    config {
        disableAllHeaderCode = 1
        additionalHeaders.10.header = Content-Type: text/plain; charset=utf-8
        admPanel = 0
        debug = 0
    }
    10 = USER
    10.userFunc = B13\AiBotsLoveMarkdown\LlmsTxt\LlmsTxtController->render
}
```
